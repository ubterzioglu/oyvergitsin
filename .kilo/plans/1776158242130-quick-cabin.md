## Adım 3: Veri Migrasyon Script'i Yaz

`scripts/migrate-data.js` — tek dosya, self-contained Node.js script.

### 3a. Script yapısı

```
migrate-data.js
├── CONFIG (eski/yeni URL + service keys)
├── Helper: fetchAll(table) → eski DB'den tüm satırları çek
├── Helper: insertBatch(table, rows) → yeni DB'ye batch insert
├── Helper: fetchAuthUsers() → eski DB auth admin API
├── Helper: createAuthUser(user) → yeni DB auth admin API
├── MIGRATION ORDER (aşağıda)
└── Main: sırayla her tabloyu migrate et
```

### 3b. Migration sırası ve detaylar

#### Faz 1: Auth Kullanıcıları
```
Eski DB: GET /auth/v1/admin/users (service key ile, paginated)
→ Tüm kullanıcıları listele (id, email, created_at, vb.)
→ Yeni DB: POST /auth/v1/admin/users (her kullanıcı için)
  - email_confirm: true
  - password: rastgele (kullanıcılar sıfırlama yapacak)
  VEYA
  - Eski DB'den password hash'i almak mümkün değil, 
    bu yüzden kullanıcılar yeni şifre belirlemeli
→ MAP: { oldUserId → newUserId } dosyaya kaydet
```

**Not:** Supabase Auth Admin API ile kullanıcı oluştururken `import` özelliği kullanılabilir. `admin.createUser()` ile UUID belirtebiliriz — böylece ID mapping'e gerek kalmaz!

```js
// Supabase JS client ile:
const { data, error } = await newSupabase.auth.admin.createUser({
  email: user.email,
  email_confirm: true,
  id: user.id,  // ← eski UUID'yi koru!
  // app_metadata, user_metadata da taşı
})
```

**Bu sayede FK reference'lar bozulmaz.**
